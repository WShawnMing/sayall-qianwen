# 千问双麦克风输入

个人 fork 的可选 macOS 功能。用户明确要求：遥控器语音键使用遥控器麦克风，实体右 Command 使用电脑麦克风，保持千问完成识别。

## 行为

- 千问固定选择 SayAll 虚拟麦克风，快捷键为右 Command，关闭短按唤起。
- 连接页提供默认关闭的「按住右 Command 使用电脑麦克风」开关。用户开启时请求麦克风权限；需要既有输入监控权限。未获得权限不启用收音。
- 实体键盘右 Command 按下时，使用用户选择的物理输入向同一虚拟麦克风送音；松开后停止采集，保留转换器尾部并排空既有输出。仅观察 HID 的 Right GUI 输入，不吞键、不合成键、不更改系统默认设备或第三方 App 设置。
- 遥控器继续沿用原按住说话路径。遥控器合成的 CGEvent 不经过物理 HID 输入回调，不能启动电脑收音。
- 两种来源交替使用，不混音。已有录音、遥控器收音或输出仍在排空时拒绝新来源；用户待停止后再按。右 Command 的松开只能结束本次按下所启动的会话，不能停止手动开始的电脑收音。
- 开启开关、启动 App、唤醒和配置导入均不能自动打开麦克风。开关只保存到本机，不随配置导出导入；另一台 Mac 需要单独启用。
- 关闭开关、键盘移除、权限丢失、睡眠和退出释放资源。收音失败、设备拔出及 120 秒超时复用已有失败/排空路径。多个键盘按住时，仅最后一个松开结束同一次收音。
- 普通 Command 组合键仍由系统和千问处理；本功能不会阻止快捷键。右 Command 已作为千问语音键使用，普通快捷键建议用左 Command。

## 验证边界

本功能只送音，不获知千问内部识别结果，也不新增音频保存或上传。软件测试验证生命周期与来源隔离，最终仍须实测实体键盘、遥控器、千问首尾字、交替输入和普通快捷键。物理松键会直接到达千问，SayAll 输出排空不代表千问已消费尾音；尾字验收不得以内部计数替代。

与上游 [PR #465](https://github.com/HD838A/remote-mic-app/pull/465) 目标相近；该候选基于较早主线并使用点按开关和独立直通引擎。本分支复用当前 Mac 麦克风会话，采用按住语义与物理 HID 观察，不合入其混音/点按实现。上游 [PR #793](https://github.com/HD838A/remote-mic-app/pull/793) 处理既有蓝牙软件键尾音，是独立待验收问题；本改动不宣称修复该问题。
